# 需求说明

## 角色与范围
- 报修人：提交报修工单，生成初始工单
- 维护人员：修改工单状态，执行维修流转
> 本项目仅实现工单状态校验逻辑，无页面、数据库、硬件通信。

## FR-01 查看设备信息
角色：报修人、维护人员
前提：工单已存在
行为与正常结果：可以读取工单当前状态
异常结果：无
验收方法：读取工单状态字段成功

## FR-02 提交报修
角色：报修人
前提与输入：报修人发起报修
正常结果：生成工单，初始状态 = PENDING
异常结果：无
验收方法：新建工单状态固定为PENDING

## FR-03 更新工单状态
角色：维护人员
允许的转换：
- PENDING → PROCESSING
- PROCESSING → COMPLETED
拒绝的转换：其余全部流转（包括COMPLETED回退、PENDING直接到COMPLETED、状态不变等）
正常结果：状态合法，更新成功
异常结果：状态流转非法，拒绝更新
验收方法：输入不同状态组合，函数给出正确允许/拒绝结果

## 已确认的实验规则
新工单为PENDING，仅允许PENDING转PROCESSING、PROCESSING转COMPLETED。
其他转换一律拒绝。本实验暂不实现完整报修系统，只实现状态判断函数。
